# 排障

先看两个地方，90% 的问题不用猜：

1. **QQ Agent 的控制台日志**：技能加载、连接、局域网发现都会打日志
2. **「技能」页那条技能的状态** + **AI 状态面板的 🎮 行**

---

## 快速对照表

| 症状 | 最可能的原因 | 处理 |
|---|---|---|
| 技能页显示加载失败 | 缺依赖 / 文件没放对 / JSON 写坏 | 见 [A](#a-技能加载失败) |
| 技能在，但状态写「依赖未安装」 | `mineflayer` 没装或装在错误目录 | 见 [A](#a-技能加载失败) |
| 一直显示「离线 · 守着局域网广播」 | 世界没「对局域网开放」/ 组播被防火墙挡 | 见 [B](#b-一直守着局域网广播) |
| 连上了几秒就掉线 | 版本不匹配 / 服务器拒绝离线身份 | 见 [C](#c-进去就掉线) |
| 进不去某个服务器 | 该服开了正版验证 | 见 [D](#d-正版验证服务器) |
| 游戏里 `!命令` 没反应 | `mcCommands` 关了 / 不在同一个服 / 命令拼错 | 见 [E](#e-游戏内-命令没反应) |
| 游戏里叫名字，QQ 群没动静 | 没绑群 / 白名单拦了 / 宿主档位没唤醒 | 见 [F](#f-叫名字群里没反应) |
| 群里说「在游戏里说 xxx」，游戏里没看到 | 用了普通消息而不是 `mc_chat` | 见 [G](#g-qq-说话游戏里听不见) |
| 它在原地转圈 / 撞墙 | 卡在地形里 / 寻路失败 | 见 [H](#h-卡住或原地打转) |
| 它越走越远找不到 | 随机游走的正常表现 | `!来` 或群里说「回来」 |
| 热重载后连接断了 | 旧实例被别的技能覆盖了 `globalThis` 状态 | 见 [I](#i-热重载后断线) |

## A. 技能加载失败

**先确认三个文件都在同一个目录：**

```
<app>/skills/mc-bot/skill.json
<app>/skills/mc-bot/index.js
<app>/skills/mc-bot/host.js
```

漏了 `host.js` 会报模块找不到（`Cannot find module './host.js'`）。注意三个文件缺一不可，`docs/`、`scripts/` **不要**一起拷进去。

**再确认依赖装在 app 根目录：**

```bash
cd "<app>"            # 包含 src/、skills/、plugins/ 的那一层
npm install mineflayer mineflayer-pathfinder vec3
```

用 Node 直接验证：

```bash
node -e "console.log(require('mineflayer/package.json').version)"
```

在 `skills/mc-bot/` 里看到的报错和这里是两回事——依赖是**向上查找**的，必须装在 `app/node_modules`。

> QQ Agent 重装 / 升级会清掉 `node_modules`，重跑一次上面的命令就行。

**最后确认 JSON 没坏：**

```bash
node -e "JSON.parse(require('fs').readFileSync('skill.json','utf8')); console.log('ok')"
```

## B. 一直「守着局域网广播」

说明它没听到世界广播。逐条排查：

1. **有没有点「对局域网开放」？** 必须点。只进单机世界不开放，没有端口可连。
2. **是不是点完又退出了那个界面？** 正常，点完直接返回游戏即可，世界仍在广播。
3. **Windows 防火墙**：UDP 4445 入站被挡时收不到组播。第一次运行 Node 时弹的防火墙提示要允许（专用网络）。
4. **主机和分身不在同一台机器？** 组播只在同一台机器/同一网段有效。跨机器请用 `host` 填对方局域网 IP。
5. **`lanAutoJoin` 被关了？** 检查设置。
6. **端口被别的程序占用**：日志会出现「无法监听局域网广播」。关掉占用 4445 的程序（或临时把 `lanAutoJoin` 关掉改用手动连接）。

手动兜底：进世界后看聊天栏提示的端口（「本地游戏已在端口 5xxxx 上开放」），群里说「连 127.0.0.1:5xxxx」。

## C. 进去就掉线

| 原因 | 日志特征 | 处理 |
|---|---|---|
| 版本不匹配 | `Unsupported protocol version` / 一直停在 connecting | 设置里把 `MC 版本` 填成实际版本，如 `1.21.4` |
| 服务器拒绝离线身份 | `You are not authenticated` / `Failed to verify username` | 无解（见 D） |
| 服务器满了 / 白名单 | `Server is full` / `You are not white-listed` | 找服主加白名单 |
| 被反作弊踢 | 自定义踢出理由 | 换个服，或只在自己世界用 |

## D. 正版验证服务器

分身的登录方式是 `auth: 'offline'`，**没有正版档案**。开了 `online-mode=true` 的服务器会在握手阶段就拒绝。

判断方法：你能用「离线启动」的客户端进去吗？能，说明服是离线模式；不能，分身也进不去。

**这是协议层的硬限制，不是配置问题。**

## E. 游戏内 `!` 命令没反应

1. 设置里 **「游戏内 ! 命令」** 是否开着（默认开）
2. 命令必须在**行首**：`!来` ✓、`喂 !来` ✗
3. 半角 `!` 或全角 `！` 都行，但中间不能有别的字符
4. 它是不是在另一个服/另一个世界？（`mc_control status` 看端点）
5. 它是不是正在被别的玩家用别的客户端同名顶号？（同名会把先连的踢掉）

## F. 叫名字群里没反应

按链路顺序查：

1. **绑群了吗？** 状态面板的离线行/`mc_control status` 会显示「聊天桥未绑定」。让它上线一次、在群里说句话，就会自动绑当前会话；或在设置里直接填群号。
2. **名字对得上吗？** 匹配的是 `username` 设置、当前 `bot.username`、人设名、人设昵称，任一命中即可，不区分大小写。你叫的如果是「小鲸鱼」而它游戏里叫「dafeiyu」，不会命中（除非人设名是那个）。
3. **`chatMonitor` 是 `off` 吗？** 那就不监听。
4. **群在白名单外吗？** 技能沿用宿主的 `allow` / `deny`；白名单非空且不含该群时，注入会被静默拦掉（这是故意的，不绕宿主权限）。
5. **宿主档位没唤醒？** 消息进群了但它没回——看群里有没有出现 `MC·玩家名：xxx`。出现了说明注入成功，是宿主的响应档位判定没到阈值，调档位或直接 @ 它。

## G. QQ 说话游戏里听不见

**两个聊天框默认不通。** 你在群里发的消息，游戏里的人看不到，除非它主动用游戏聊天发。

正确的说法：「**在游戏里说一句 xxx**」→ 模型调用 `mc_chat`。

反过来，游戏聊天进 QQ 需要：`relayToQQ` 开（原样转发）或 `chatMonitor` 命中（叫名字）。

## H. 卡住或原地打转

- 地形卡死（掉坑、被方块围住）：`!来` 不一定有效，用 `mc_dig` 挖开，或 `mc_cmd tp` 传出来
- 目标不可达（在墙里/水里/悬崖上）：寻路会失败并停在原地，换个坐标
- `exploreDig` 关着时被挡就真的走不过去，这是刻意的
- 觉得它晃得烦：`!停` 或把 `autoExplore` 关掉

## I. 热重载后断线

正常情况下不会：状态挂在 `globalThis.__MCBOT_STATE`，`deactivate({reason:'reload'})` 直接返回不拆连接。

如果确实断了，通常是：

- 手改了 `index.js` 且写坏了（语法错误 → 新实例加载失败，旧实例已被卸载）
- 另一个进程（第二份 QQ Agent）也在跑同一个技能，`globalThis` 各是各的，但会**同名顶号**
- 升级/重装宿主后进程整个重启了（这是重启，不是热重载）

## 彻底重置

1. **只重置设置**：删掉 `data/config.json` 里 `skills.mc-bot` 这一段，重载技能即回默认值
2. **卸载技能**：删掉 `<app>/skills/mc-bot/` 整个目录；备份在 `<app>/.mc-bot-backup/`
3. **连依赖一起清**：在 `<app>` 里 `npm uninstall mineflayer mineflayer-pathfinder vec3`（注意：宿主的 `package.json` 里也列了 mineflayer，卸载前确认没有别的功能在用）

```bash
node -v
cd "<app>" && npm ls mineflayer mineflayer-pathfinder vec3
node --check skills/mc-bot/index.js
node scripts/selfcheck.mjs        # 在仓库里跑
```

加上 QQ Agent 控制台里与 `mc-bot` 相关的日志（含 `⚠️` 那几行），基本能定位。
